# Security policy

## Supported versions

Security maintenance targets the latest published MineCode release on a best-effort basis, including a pre-release while no stable release is available. Older versions and development snapshots have no guaranteed backports.

## Report a vulnerability privately

Private vulnerability reporting is enabled for [uruk-king/MineCode](https://github.com/uruk-king/MineCode/security/advisories). Use **Security → Advisories → Report a vulnerability** to submit a private report to its maintainers. Include the affected version, minimal reproduction, likely impact and relevant permission flags. Use synthetic credentials and sanitized examples; do not attach personal data or live secrets.

Do not disclose exploitable details in public issues or pull requests. If the reporting button is unavailable, open a non-sensitive issue asking maintainers how to report privately; omit the vulnerability details. Ordinary non-sensitive defects can use the normal issue tracker.

## Maintenance and disclosure

Reports, fixes and coordinated disclosure are handled as maintainer availability permits. There is no guaranteed response deadline, ongoing support schedule or bounty. Prefer a focused fix and release for a confirmed issue. MineCode's execution opt-ins and best-effort output redaction are not an OS sandbox or an absolute secrecy guarantee.
